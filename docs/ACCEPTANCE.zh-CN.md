# Hindsight 记忆工作台验收清单

本清单区分 npm 离线装包、DSH 宿主挂载、真实后端读写三层证据。一层通过不能替下一层签字。测试只使用独立 DSH 配置目录、隔离后端和合成文本；不能导入个人会话、凭证或旧库正文。若平台无法证明隔离，不启动验收。

## 可重复的装包检查

在源码目录运行 `npm run build`、`npm test`、`npm run smoke:package`。最后一项将实际归档装到临时 npm 工程，不读取当前 DSH profile。记录 OS、Node 版本、npm 版本和退出状态。

## 干净 DSH 安装及故障恢复

1. 记录 OS、DSH 版本、包版本、安装来源和独立配置目录。通过官方管理器装包；验证 GUI 上出现侧栏、正确标题、安装与检查入口。仅模块可 import 不算通过。
2. 首次打开保持后端未启动。应区分未连通、未确认模型授权和上游未挂载；不开启后台下载、服务启动或对话采集。经明确批准后再验证实际依赖安装、服务启动和目标机器上的模型授权。
3. 用本地测试后端分别验证缺库、断连、鉴权拒绝和不支持接口。检查界面标明失败来源、不偷偷回退到其它库、不泄露诊断原文里的路径或凭证。
4. 使用官方管理器撤销本次测试变更。验证页面和插件路由撤销、无关插件无变化；若切换过采集器，恢复原先唯一采集器且验证新旧不会同时工作。后端旧数据保持原状。仅 npm 工程清理不算回退通过。

## 两个同名未手绑项目与单采集

隔离原型可用 `npm test` 复跑：它使用临时目录和模拟 HTTP 后端，验证同名项目、路径别名、会话身份变化和写入结果未知时不重试。它没有注册实际 DSH 采集器，也未证明后端已落库。以下步骤才是产品验收：

1. 创建两个末级目录名相同、绝对路径不同的测试项目，各开一个独立 DSH 会话，不设置项目映射；再开一个拥有独立测试标记的全局库。记录两个会话的宿主身份和真实库 ID。不要通过手输 bank 来伪造页面选库。
2. 用合成事实标记 A、B、G。分别验证：A 项目只能读取 A 和 G，B 项目只能读取 B 和 G；来源标记与后端实际请求一致。检查页面详情、自动召回和后端读写记录，而不是只凭模型回答判定。先设定等待上限；写入只有在后端确认落库后才算通过，队列接受不算。
3. 每个测试会话提交一条独特合成事实。确认只有一个采集器处理每回合、只写项目库、全局库及另一项目库未被修改。若原项目身份不可用，应拒绝项目读写，不退回最近使用库、默认目录或另一个项目库。
4. 切换会话、重开、工作目录变化和并发读写时重复核查。项目身份规则应明确何时保持会话原项目、何时需要开新会话；界面与后台不能各用一套规则。
5. 在隔离后端使用合成旧库验证回退。比较旧库内的测试标记和记录数，确认没有复制、重命名或删除；独立记录本轮新库是否仍保留，不把切换采集器误报为数据库恢复。

## 发布门

维护者在源码目录运行 `npm run check:public-pack`，检查归档文件白名单、私有包标识及已知本机配置标记。该预检只输出问题和文件名，不输出命中的原文，也不能替代公开源码及归档的人工审查。预检失败时不得发布；不要为了让本地开发包通过而改动活动安装提供的包标识或配置。

逐平台单独记录验收结果；本地 npm 检查不代表任何平台完成 DSH 挂载。受控进化、知识导入、全局提升和 Skill 采纳要另验单动作确认、失败状态和回退，不能借本清单自动执行。公开制品不得含个人配置、日志、会话、凭证或记忆数据。清单通过也不自动授权部署、推送或上架。
