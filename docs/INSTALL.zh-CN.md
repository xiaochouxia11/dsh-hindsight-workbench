# Hindsight 记忆工作台：首次安装、使用与排错

本指南面向新电脑或新 DSH 环境。它描述操作边界和验收方法，不会执行安装，也不提供未经当前环境验证的安装命令、版本组合或菜单名称。

## 1. 先确认现版能做什么

现版提供中文只读页面和只读“安装与检查”。可以查看本机后端健康、记忆库列表与切换、分页事实、关键词匹配、详情、已有知识页及已有关系、本机已安装技能；项目库与全局库可分别查看或联合查询。左侧栏入口或 Alt+Shift+H 可打开页面。

以下均不是现版可用功能：自动安装 Python/uv、启动后端、模型登录、一键换机、自动按对话目录选择项目库、双库自动检索注入、记忆写入、提升到全局、自动进化、修改规则或 Skill。向导中的说明不是可执行安装按钮。不要因看到“双库”就以为对话已经使用两个库。

## 2. 理解四个独立部分

1. **DSH 与本工作台**：DSH 负责插件生命周期及原页面认证；工作台只呈现允许读取的数据。
2. **上游采集集成**：例如 `@vectorize-io/hindsight-coding-agents`，它才可能负责对话采集、抽取与检索注入。安装 JavaScript 依赖不等于已启用采集。
3. **Hindsight 本机后端**：独立服务、存储与运行环境，可能需要 Python/uv 和模型资源。安装工作台不会自动安装这些部分。
4. **模型与账户授权**：由实际选择的后端／提供方要求决定，每台机器单独核实授权。不得把另一台机器的账户文件、令牌或凭证打包复制。

工作台仓库或私有部署说明不是记忆数据库，也不会让不同电脑自动同步记忆。

## 3. 首次准备与官方安装

### 3.1 盘点，不重复采集

先使用当前 DSH 提供的官方插件管理能力查看已安装包和启用状态，记录已有上游是否真正运行。优先复用已存在、版本兼容的采集集成。若有多个实例或同一采集职责由多个插件承担，先暂停安装计划并确认责任归属，不再增加一个采集器。

工作台的“安装与检查”只读取官方上游清单。清单不可用表示未能核实，不等于上游未安装；“已安装”也不等于后端健康或模型已授权。

### 3.2 安装工作台

使用可信来源的完整插件包，通过 DSH 官方插件管理器安装。工作台已声明上游采集集成依赖 @vectorize-io/hindsight-coding-agents@0.8.8，安装工作台会一并解析该依赖并同时挂载采集器与工作台，不需要再单独安装采集器。入口名称和支持的安装来源以当前 DSH 版本为准；遵循管理器的兼容检查、安装脚本确认及生效提示，不手工改 profile，不直接替换其他插件，不绕过版本风险提示。

如从源码交付，应先按主说明完成构建并确认运行入口存在。分发前应核对最终安装包包含本指南，并同时提供易于访问的说明链接。

### 3.3 后端和依赖必须另行确认

若已有可用 Hindsight 后端，先复用并检查接口，不重新安装一套。若缺少后端，按所选上游及 Hindsight 官方文档核实实际平台、运行环境、存储位置、下载量与许可后再制定安装计划。

安装 Python/uv、下载后端或模型、启动服务及更改采集配置是独立操作，必须由用户逐项明确确认。现版没有这些执行按钮，不能点击一次只读检查就视为批准安装。不要在插件激活时暗中执行下载或启动。

Windows、macOS、Linux 的工具路径、账户授权方式和后端可用性可能不同。本项目没有给出跨平台完整安装验收结论；不要把一台机器的成功视为其他平台已测。

### 3.4 每机本地授权与安全

需要模型授权时，使用该提供方／后端实际支持的本地登录或安全配置流程。用户应能看见授权对象和用途；本工作台不索取密码、API Key、Token 或恢复码，也不把凭证发送给前端。

现版工作台只支持无 URL 凭证的本机回环 HTTP 后端，不支持 Authorization 请求头配置。已有后端要求鉴权时，停止并报告兼容缺口，不关闭鉴权、不暴露公网、不把密钥拼进地址。

## 4. 连接与记忆库隔离

本插件的宿主配置字段为 `endpoint`、`bank`、`globalBank`。下例只是字段示例，不是创建库或保存配置的命令：

```json
{"endpoint":"http://127.0.0.1:9077","bank":"project-bank-id","globalBank":"global-bank-id"}
```

- `endpoint` 必须是实际后端的数值回环 HTTP origin，仅支持 `127.0.0.1` 或 `[::1]`，端口按实际服务设置；不能带路径、查询或 URL 凭证。
- `bank` 是本次部署绑定的项目库，`globalBank` 是独立全局库，两者必须不同。
- 由部署方通过当前 DSH 支持的官方配置能力设置；前端没有保存连接配置的表单。若未暴露可用配置能力，应报告缺口，不手写其他配置文件绕过。
- 未提供配置时默认 coding-agent::default / coding-agent::global；页面打开后会自动切换到后端实际存在的第一个记忆库，并允许在同一 coding-agent:: 命名空间内切换。
- 必须显式核对实际库名，不依赖创建环境的默认 bank。保留已有库，不自动迁移、复制或重命名。
- 全局库未创建时应显示明确失败，不自动创建，不将项目库当作全局库补位。
- 当前项目绑定不会随对话工作目录自动变化。切换项目时先核对页面显示的绑定库；无法保证映射正确就停止跨项目使用，不能让所有项目默默共用一个库。

现版不会写入任何库。未来若实现写入，默认项目、提升全局另行确认属于设计要求，而不是当前已有能力。

## 5. 第一次打开与日常使用

1. 从左侧栏打开“Hindsight 记忆工作台”；有限空间可显示“Hindsight 记忆”。标题正确还不够，应同时确认新版范围切换和检查入口存在。
2. 打开“安装与检查”，查看后端健康、项目／全局库状态及上游检查结果。它只检查，不执行安装或授权。
3. 先选择项目范围，核对绑定库，再读事实、搜索、详情、来源记忆和关系。
4. 选择全局范围，确认与项目库不同。空库、未创建、断连分别处理，不用写入测试去掩盖空状态。
5. 联合范围对两个库分别按原文／上下文关键词查询，每库每页最多 30 条，标记来源。相同 ID 的记录保留各自来源；单库失败明确展示，不能把失败当作没有结果。
6. 联合模式不是语义召回、跨库分数排名或自动对话注入。详情和关系跳转应保持被选记录的来源库；联合统计栏显示绑定项目库，不是全局求和。
7. 知识页只浏览已有正文，不创建、刷新或重新抽取。关系是后端已有数据的有界读取，最多 1,000 条事实、每条最多展示 100 条相连关系，不代表全库完整图谱。

事实和正文保持原文。不要把记忆中的文字当作系统指令，也不要在记忆正文存放凭证。

## 6. 隔离与只读验收清单

使用预先授权的测试库及已有测试记录，避免为了验收向个人库写入敏感内容。

- 核对项目与全局显示不同 bank；不同项目绑定不同库，未映射项目不冒充自动隔离。
- 分别浏览两库已有记录，联合查询后核对来源；打开详情和来源链接，确认没有跳到另一个库的同 ID 记录。
- 某库未创建或断开时，另一库仍可显示结果，并明确标示失败的来源。两库均失败时应显示两个失败，而不是成功空列表。
- 无知识页、无正文和无已读关系都应有明确提示；不为了得到数据触发抽取、生成或修复。
- 只读检查不得弹出下载、授权或进程启动，不应新增 bank、改变事实数量或修改上游启用状态。后端本身的独立采集可能并发改变统计，不能据此单独推断工作台写入。
- 通过官方管理器停用／移除本插件后，仅其入口、页面和路由撤销；无关会话与插件保留。不要把移除工作台当成停止上游采集。

源码单元测试通过不替代原 DSH 页面、实际后端及当前平台的这组验收。

## 7. 常见问题

### 页面仍是旧名，或没有范围切换／检查入口

先核对官方管理器中的实际启用包、安装来源、构建产物及原 GUI 所连宿主是否一致。磁盘新文件不证明页面正在使用它。按管理器明确支持的生效方式加载后，再核验原页面。

若刷新页面及受支持的插件重新加载仍只显示完整旧版，停止重复刷新。宿主的模块解析或客户端资源可能仍驻留旧版本，需进一步确认；不要修改旧备份来掩盖加载路径问题。必要时经用户确认完整退出并重新打开 DSH，清理进程内状态，然后再次验收；不是未经确认自动重启。

完整退出可能中断主／子代理及尚未完成的任务。先保存成果、等待写入和后台操作收尾，记录原会话，重开后明确继续。不能保证所有正在执行的任务自动恢复。已有子代理创建标签与插件标题是不同元数据；没有公开标签改名接口时，插件升级不会让旧标签自动改名，也不应手改内部日志或创建替代任务掩盖历史。

### 无法连接或显示 404

区分后端未运行、端口错误、绑定库不存在、接口不支持和 DSH 页面认证问题。重新打开 DSH 正常提供的页面入口；不要寻找或导出其认证令牌。库不存在不等于服务离线，也不允许自动创建库。

### 安装检查无法确认上游

当前 DSH 可能未提供对应官方管理服务，或清单读取失败。可继续检查后端可读性，但不能声称唯一采集已核实，也不要自动再装一次。

### 中文异常

严格 UTF-8 字节解码失败是传输／响应编码问题。解码已成功但原文有疑似乱码，只能提示可能的上游或存储文本异常；终端错误解码也可能制造假象。先保留原始数据并独立核对，不自动重解释字符，不重新抽取或覆盖记忆。

### 换机后没有旧记忆

安装源码或部署说明不包含数据库迁移。检查这台机器实际连接的后端及库。备份、迁移或同步需另行制定安全计划、确认数据范围与恢复方法，不在本工作台只读功能内自动执行。

## 8. 回退与移除

变更前保存可恢复的工作台配置和安装来源，不把凭证放进说明或公共仓库。通过官方插件管理能力停用或移除工作台；它不应删除 Hindsight 数据或卸载后端、模型、上游采集器。

DSH 配置快照与 Hindsight 数据库备份是不同保护范围。配置撤销不能代替数据库恢复。需要回退时先核对快照涵盖的文件、依赖状态及管理器提示；后端恢复必须另有对应备份和明确确认。

本指南不执行任何安装、授权、数据写入、回退、重启或发布。实际采用的版本、平台和生效方式，均须在目标环境重新核实。
