# 公开发布与插件市场验收（维护者）

本清单是发布门，不是已发布的声明。现有本地开发插件与公开包分开，不用改活动 Profile 的包名来通过预检。

1. **验证功能。** 使用隔离配置、隔离后端和合成事实，执行 [验收清单](./ACCEPTANCE.zh-CN.md)。特别核查同名不同路径的两个未绑定项目、项目写入与联合召回、安装后启用和卸载回退。只有 npm 装包或模拟后端时不算真实 DSH 验收。若某项仅在实验分支通过，不写进正式版本功能声明。
2. **审查公开制品。** 另建干净的发布目录，逐项允许通用源码、测试、构建脚本、使用/故障说明和授权明确的素材；禁止整个工作区镜像或历史推送。核查公开源码及 tarball 均不含本机默认库、路径、用户名、本地包标识、个人配置、会话、日志、凭证或真实记忆。确认许可、公共包名、精确版本、构建产物、DSH 兼容范围与 GitHub `repository` 元数据。生成包后记录 SHA-256。
3. **发布到 GitHub。** 在公开仓提交已审核的通用源码，标记 `dsh-plugin` 主题，发带同版本 `.tgz` 的 Release。当前 dsh-m Desktop 的 GitHub 回退会从 tag 解析提交并安装源码树，不能只验证 Release 附件；tag 内应带可直接安装的构建产物，或另行验证有匹配仓库元数据的公共 npm 精确版本。在未带本地源码的隔离 DSH 环境验证最终采用的来源、启用及卸载。私有部署文档另存；只放说明与无凭证模板。
4. **提交社区目录。** 按 [Awesome DSH Plugin 投稿指南](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/blob/main/contributing.md) 提交条目，不向消费该目录的市场客户端投稿。以投稿时的当前规则为准。待维护者合并、目录构建分发后，核对消费方实际索引与安装来源。
5. **验证端到端安装。** 分别记录 GitHub Release 可公开下载、目录 PR 状态、目标市场能搜到、全新 Profile 从市场卡安装并激活四件事。若目标包括 DSH 原生「发现」，社区目录的 [索引生成器](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/blob/main/scripts/build-index.mjs#L3-L13) 会跳过没有已发布 npm 版本的条目；npm 元数据还须能关联公开仓库。用户需自行启用该社区索引；目录合并后还要等待索引发布。这些条件只适用于该社区索引：DSH 原生「发现」也支持由维护者另行托管的、固定 Git 提交的 format-1 索引，但用户仍需主动添加它，它不等于社区市场收录。第三方评审、合并和传播未完成时只报告实际进度。
